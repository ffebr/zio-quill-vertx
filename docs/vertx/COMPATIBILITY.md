# Матрица совместимости и миграции

Цель — выполнять прежние Quill QDSL expressions и сохранять их наблюдаемую PostgreSQL семантику через native Vert.x backend. Изменение backend wiring разрешено; переписывать QDSL expressions, shared test expressions или expected values запрещено. JDBC-only interfaces и callbacks переходят на документированные native seams и не входят в drop-in обещание.

Пути ниже относительно корня репозитория. Реализация и native runners находятся в `quill-vertx-zio`; фактически проверенные сценарии перечислены в [TEST-MATRIX.md](TEST-MATRIX.md), результаты запусков — в [VALIDATION.md](VALIDATION.md). Строки таблицы задают контракты приёмки и сами по себе не означают полное покрытие.

| Контракт | Текущий источник / migration seam | Доказательство приёмки |
| --- | --- | --- |
| QDSL expressions | `quill-core`, `quill-sql`, `quill-test-kit/src/test/scala/zio/quill/context/sql` | Те же `quote`/`query`/`lift`, operators, actions, returning и shared assertion bodies перекомпилируются с native context. Context-bound quotations можно заново скомпилировать; выражения и expected values не редактировать. |
| Native context и ZIO environment | Текущие `quill-jdbc-zio/.../jdbczio/Quill.scala`, `QuillBaseContext.scala`; новый API в `quill-vertx-zio` | Явный native pool/config/layer, ZIO result/error/environment types, ownership и lifecycle. Записать миграцию старых imports/context construction; не сохранять `DataSource`/`Connection` типы искусственной эмуляцией. |
| Native dependency isolation | `build.sbt`, `quill-jdbc-zio` как исходный JDBC reference | Отдельный native module использует core/SQL macros и ZIO; dependency/runtime classpath не содержит `quill-jdbc`, pgjdbc или Vert.x JDBC client. Если общие QDSL data-only types требуют source extraction, native и JDBC closures зависят от одной лёгкой shared artifact с сохранёнными FQCN; двух class definitions нет. |
| JDBC custom codecs | `quill-jdbc/src/main/scala/zio/quill/context/jdbc/Encoders.scala`, `Decoders.scala`, `JdbcContextTypes.scala` | Инвентаризировать существующие callback codecs и дать явную migration mapping на native encoder/decoder API. Проверить built-in, custom/mapped, null/option и encode/decode parity; JDBC `PreparedStatement`/`ResultSet` callbacks не обещаются как совместимые. |
| PostgreSQL arrays/UUID/JSON | `quill-jdbc/.../ArrayEncoders.scala`, `ArrayDecoders.scala`, `UUIDObjectEncoding.scala`; `quill-jdbc-zio/.../context/json/PostgresJsonExtensions.scala`; shared wrappers in `quill-zio/src/main/scala/zio/quill/JsonValue.scala` (moved unchanged from `quill-jdbc-zio`) | Native round-trip массивов/null elements, bytea, UUID, JsonValue/JsonbValue и исходные JSON cases на обеих поддерживаемых Scala версиях. Wrapper types доступны native без зависимости на JDBC backend через общий data-only artifact, сохраняя FQCN и value semantics. Документировать переход с PGobject/JDBC-specific codecs. |
| Даты/время/числа | JDBC `Encoders.scala`, `Decoders.scala`, `SimplifiedContexts.scala`; shared `EncodingSpec` | Сравнить precision/scale/overflow, temporal precision/timezone, DST, nanoseconds, UUID и booleans с JDBC reference; фиксировать PostgreSQL precision. Переводить custom JDBC calendar callbacks в native codecs явно. |
| SQL translation и bind markers | `quill-core`, `quill-sql`, `ZioTranslateContext`; новый native translator | Shared SQL/query tests сохраняются. Bind values остаются параметрами; native PostgreSQL placeholders корректны для литералов, обычных и escape strings, quoted identifiers, comments, dollar-quoted bodies и PostgreSQL operators, включая `?`. QDSL не переписывается для рантайма. |
| Query/cardinality/action | `quill-jdbc/.../JdbcContextVerbExecute.scala`; shared `quill-test-kit` suites | Empty/many/single, ordering, affected rows и failures совпадают по значению/side effect. Те же query/action expressions и ожидаемые результаты; сравнение на независимо reset JDBC/native schemas. |
| Returning/generated keys/batch | JDBC execute и `ReturnAction`; shared returning/batch specs | `returning`, `returningGenerated`, `returningMany`, record/columns/nothing, grouping/order/counts, empty input и partial failure дают те же наблюдаемые результаты. |
| Transaction/fibers | `quill-jdbc-zio/.../context/qzio/ZioJdbcContext.scala`, `ZioJdbcUnderlyingContext.scala` | Commit/rollback на typed failure, defect и interruption; nested reuse как у reference без новых savepoints; transaction-bound streams и определённое concurrent child-fiber поведение. Нет записи после rollback, ресурсы освобождаются при каждом exit. |
| Streaming/fetch size | `ZioJdbcUnderlyingContext.scala`, `ResultSetIterator.scala` | Incremental bounded-memory reads, backpressure/fetch size, early take, empty results, consumer failure, interruption, чтение внутри транзакции и cleanup. Native stream не заменяется `collectAll`. |
| Prepare/probe escape hatches | `quill-jdbc-zio/src/test/scala/zio/quill/PrepareZioJdbcSpecBase.scala`, `context/qzio/ZioPrepareContext.scala` | Инвентаризировать legacy `prepare`, `prepareParams`, `probe`, JDBC metadata/unwrap и custom session callbacks. Для реально используемых операций дать migration guidance и native API equivalents; JDBC `PreparedStatement`/`Connection` signatures и произвольный vendor unwrap не эмулировать. Проверить прежнюю SQL/prepare семантику через native replacement tests. |
| Ошибки и cancellation | JDBC/ZIO execution; новые native tests | SQL/constraint/auth/connection/timeout failures сохраняют типизированную ошибку, причину и доступные SQLState/vendor fields; error/defect/interruption не смешиваются. Проверить отмену acquire/query/fetch/commit и отсутствие оставшихся запросов/ресурсов. |
| Фактическое native исполнение | Новые диагностические/integration tests | Инструментировать backend selection; каждый тест native проходит через Vert.x PostgreSQL transport. JDBC execution и silent fallback невозможны. Проверить event-loop heartbeat и resource cleanup. |
| Реальное приложение | Black box недоступен агентам | Пользователь получает migration inventory, меняет разрешённую integration boundary без правок QDSL и подтверждает сборку/workload. До этого app-specific migration остаётся непроверенной; библиотечные тесты не объявляются доказательством конкретного приложения. |

Другие БД сохраняют JDBC реализации. Существующие H2/MySQL/SQLite/SQL Server/Oracle JDBC suites остаются неизменными регрессионными проверками. Scala 3 не заявляется для JDBC-ZIO; поддерживаемые версии нового модуля фиксируются отдельным build решением.

## Явно мигрируемые элементы

К migration inventory относятся imports нового backend, context construction, ZIO pool/config/layers, любые JDBC custom encoder/decoder callbacks, raw prepare/probe/session usage, прямое обращение к `DataSource`/`Connection` и vendor-specific APIs. Каждая обнаруженная форма должна иметь новое использование и тест, если она нужна приложению. Эти изменения не дают права менять QDSL expressions или shared expected values.
